# Project Specification: Greek Flashcard & Audio Asset Builder (Local-First PWA)

## 1. Project Purpose & North Star Goals

### 1.1 Context & Core Objective
The objective is to build a local-first, single-user authoring workstation and study engine for learning Modern Greek. The primary goal is **high-quality deck authoring and asset generation** (specifically native-sounding Greek audio via Google Cloud TTS Chirp 3), with a secondary goal of producing an exportable, self-contained Progressive Web App (PWA) runnable offline on mobile devices.

### 1.2 Target Audience & Usage Lifecycle
* **Sole User:** A single learner/curator running the app locally on a personal computer (macOS/Linux/Windows).
* **Workflow Phase 1 (Authoring & Asset Generation):** The user or AI agents draft lesson entries in human-readable YAML files. The user previews audio generated by Google Cloud TTS Chirp 3, accepts or rejects each pronunciation, and persists verified audio to disk.
* **Workflow Phase 2 (Study & Export):** The app provides an interactive flashcard review mode. Once a deck is finalized, an automated build script exports a static, zero-backend PWA bundle containing all YAML data (compiled to optimized JSON) and generated `.mp3` assets, ready to be hosted on Cloudflare Pages, GitHub Pages, or a local network share for mobile use.

### 1.3 Guiding Architectural Principles
1. **File System as Single Source of Truth:** No SQL, NoSQL, or browser database (IndexedDB) acts as the primary database during authoring. Local YAML files store all card data, lessons, and metadata.
2. **AI-Agent Friendly:** Splitting content into modular YAML files allows external LLMs to draft or expand lessons without merge conflicts or context-window limits.
3. **Deterministic Audio Asset Caching:** Audio is generated on demand, reviewed in-memory, and saved to disk using a content-hash slug. An audio file is generated **once**, vetted, and reused indefinitely.
4. **Zero Overhead & Simplicity:** Minimalist tech stack. Avoid authentication, user accounts, multi-tenancy, or unnecessary microservices.

## 4. Key Workflows & Features

### 4.1 Central Tracking Dashboard (Dynamic Rollup)
The app must automatically scan `content/` and calculate real-time statistics whenever cards are added, modified, or verified:
* **Global Metrics:**
  * Total Units, Total Lessons, Total Vocabulary Entries.
  * Audio Health: Verified Count ($N$), Pending TTS ($N$), Rejected/Needs Review ($N$).
  * Coverage Percentage: $\frac{\text{Verified Audio}}{\text{Total Cards}} \times 100\%$.
* **Unit/Lesson Breakdown:**
  * Progress bars per lesson showing verification completeness.
  * Direct action buttons: "Start Lesson Drill", "Batch Generate TTS", or "Review Pending".

### 4.2 The TTS Chirp 3 Review Pipeline ("Listen, Accept or Reject")
The application must **never** save Chirp 3 audio directly into the deck without explicit user confirmation.
1. **Trigger:** User clicks "Generate TTS" on an entry in the UI.
2. **Synthesis Request:** UI sends `{ text: "Καλημέρα", entryId: "grk-001" }` to the local backend.
3. **GCP Call:** Backend calls Google Cloud TTS using the Greek Chirp 3 model (`el-GR-chirp-3-*` or modern Chirp Greek voice).
4. **Preview in Memory:** Backend returns the audio stream (e.g., as `audio/mp3` or base64 data URI). The UI loads this into an HTML5 `<audio>` player and automatically plays it.
5. **Decision Interface:**
   * **Button A: Accept (Green):**
     * UI sends a `/api/tts/accept` request with the audio buffer reference.
     * Backend hashes the Greek string (e.g., `slugify("Καλημέρα") + "-" + md5(greek).slice(0, 6) + ".mp3"`), writes the file to `/audio/kalimera-3a7f8e.mp3`, updates the corresponding YAML entry (`audio: "kalimera-3a7f8e.mp3"`, `status: "verified"`), and writes back to disk.
   * **Button B: Reject (Red):**
     * Audio buffer in memory is discarded. No file is written to `/audio`.
     * Entry is tagged with `status: "needs_review"`.
     * UI presents an inline text editor allowing the user to adjust the Greek spelling or accents (*tonos*) before re-synthesizing.

### 4.3 Deterministic Audio Filename Strategy
To prevent duplicate files and keep audio references portable:
```typescript
import crypto from 'crypto';

export function generateAudioFilename(greekText: string): string {
  // Transliterate or clean Greek characters for safe filesystem naming
  const cleanSlug = greekText
    .normalize("NFD")
    .replace(/[\u0300-\u036f]/g, "") // Remove diacritics for the slug
    .toLowerCase()
    .replace(/[^a-z0-9α-ω]/g, "-")
    .replace(/-+/g, "-")
    .slice(0, 20);

  // Hash the original Unicode text (preserving diacritics/accents)
  const hash = crypto
    .createHash('sha256')
    .update(greekText.trim().normalize("NFC"))
    .digest('hex')
    .slice(0, 6);

  return `${cleanSlug}-${hash}.mp3`;
}
```

### 4.4 Study Mode (Flashcard Drill)
A clean, minimal study view:
* **Card Face (Prompt):** Displays Greek text, gender/part of speech badge, and an audio speaker button (auto-plays if audio exists).
* **Card Back (Reveal):** Displays English translation, phonetic guide, and usage notes.
* **Navigation:** Next, Previous, Shuffle, and Mark for Review buttons. Keyboard shortcuts (`Space` to flip, `ArrowRight` for next, `R` to replay audio).

## 5. Local Server API Specifications

The local backend (Node.js/Express) exposes simple REST endpoints on `http://localhost:3000/api`:

| Method | Endpoint | Description |
| :--- | :--- | :--- |
| `GET` | `/api/deck` | Reads `manifest.yaml` and all referenced lesson files; returns complete parsed JSON tree. |
| `POST` | `/api/entry` | Adds a new entry to a specified `unit_id` and `lesson_id`, writes to the corresponding `.yaml`. |
| `PUT` | `/api/entry/:id` | Updates an existing entry (text, notes, status), writes back to the YAML file. |
| `POST` | `/api/tts/preview` | Calls GCP Chirp 3 for provided Greek text. Returns temporary audio stream / base64 without saving. |
| `POST` | `/api/tts/accept` | Takes temporary audio session ID, commits `.mp3` to `/audio`, updates entry's `audio` and `status` in the YAML. |
| `GET` | `/audio/:filename`| Static file server serving saved MP3 files from `/audio`. |
| `POST` | `/api/export` | Triggers the build script to generate the static PWA distribution folder. |

### 6.2 TTS Client Configuration
```typescript
import textToSpeech from '@google-cloud/text-to-speech';

const client = new textToSpeech.TextToSpeechClient();

export async function synthesizeGreekChirp(text: string): Promise<Buffer> {
  const request = {
    input: { text },
    // Configure voice for Greek Chirp 3
    voice: {
      languageCode: 'el-GR',
      name: 'el-GR-Chirp3-HD-F', // Or user-selected Chirp 3 / Neural2 Greek voice
    },
    audioConfig: {
      audioEncoding: 'MP3' as const,
      speakingRate: 0.9, // Slightly slowed for language learners
      sampleRateHertz: 24000,
    },
  };

  const [response] = await client.synthesizeSpeech(request);
  return response.audioContent as Buffer;
}
```

## 7. Static Mobile PWA Export Script

The project must include an automated export script (`scripts/export-pwa.ts` executable via `npm run export:pwa`):
1. **Compile Data:** Reads `content/manifest.yaml` and all `lesson-*.yaml` files, bundles them into a single, compact `dist-pwa/data/deck.json`.
2. **Copy Assets:** Copies all verified `.mp3` files from `/audio/` into `dist-pwa/audio/`.
3. **Build Frontend:** Invokes Vite build with static PWA configuration:
   * Sets up a Service Worker caching `deck.json`, all `.html`/`.js`/`.css` assets, and pre-caching or caching-on-access all `./audio/*.mp3` assets.
   * Produces a standalone `dist-pwa/` folder that can be directly deployed to GitHub Pages, Cloudflare Pages, or served locally with `npx serve dist-pwa`.
4. **Result:** On mobile, the user visits the deployed URL once, taps "Install App" / "Add to Home Screen", and has the complete Greek deck and native audio fully functional with **zero internet connection required**.

## 8. Guardrails & Explicit Instructions for the AI Coding Agent

When implementing this codebase, adhere strictly to the following instructions:

1. **Do Not Introduce Heavy Databases:** Do not install SQLite, PostgreSQL, MongoDB, or Prisma. The local file system and YAML files are the database.
2. **Preserve Greek Tonos (Accents):** Greek text must always be normalized using Unicode `NFC` (`string.normalize('NFC')`). Dropping accents will break both TTS pronunciation and grammatical validity.
3. **Safe YAML Writing:** When writing back to YAML files, preserve array order, clean formatting, and human readability. Use `js-yaml.dump(..., { indent: 2, lineWidth: -1 })`.
4. **Atomic Audio Writes:** Never write partial audio files to disk. If the network drops or GCP fails during preview, fail gracefully, notify the UI via an error toast, and leave the YAML unchanged.
5. **UI Accessibility & Polish:**
   * Build the UI with Tailwind CSS. Provide a dark/light mode toggle.
   * Ensure audio buttons show loading spinners while TTS is generating.
   * Provide immediate visual feedback when an audio track is accepted or rejected.
